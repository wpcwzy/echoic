## 1. 背景与问题定义

### 1.1 现象：录音被保存，但没有被理解

会议、访谈、组会、客户通话每天都在产生录音，但大多数录音的命运是：**存进网盘 → 再也没有打开**。原因不是用户不想复盘，而是复盘的边际成本太高：

- **不可检索**：音频是黑盒，想找“谁在哪一分钟说了交付时间”，只能拖进度条盲听。
- **不可引用**：即使有转写，结论与原始发言脱节，写论文、写复盘时无法快速回到证据。
- **不可复用**：一场 60 分钟的会，真正有价值的可能只有 5 条结论、3 个待办、2 个风险；它们散落在录音里，无法进入知识库、任务系统或下一篇文档。
- **不可信任**：把未公开的研究访谈、客户通话、法务沟通上传到 SaaS，意味着数据离开自己的控制范围；对隐私敏感组织，这直接排除了公有云方案。
- **不可运维**：传统自建方案要装数据库、消息队列、对象存储、转码服务，个人和小团队没有精力维护。

### 1.2 问题陈述

> **如何让“录音 → 可检索、可引用、可复用的知识资产”这件事，完整地发生在用户自己的服务器上，并且一个人用一条命令就能维护？**

拆解为四个必须同时满足的条件：

1. **闭环**：上传/录音、转写、纪要、结构化观点、章节、问答、搜索、导出必须在一处完成，而不是五个工具拼接。
2. **主权**：媒体、转写、向量、密钥默认落在本地卷；只有用户显式配置的 AI 服务才产生出站请求。
3. **低运维**：单容器、SQLite、内嵌任务队列，不强制 Redis/Postgres/对象存储。
4. **可验证**：没有 API Key 也能用内置示例跑通全流程，便于评估、演示、教学与自动化测试。

### 1.3 产品定位

**Echoic = paperless-ngx 之于录音/视频。**

paperless-ngx 把纸质文档变成可搜索、可标签化、可工作流处理的私人档案；Echoic 把会议录音与视频变成可搜索、可引用、可结构化复用的私人知识库。它不是“另一个会议软件”，而是**事后的知识沉淀层**：不抢会议入口，不要求组织迁移，不绑定某一家 ASR/LLM。

一句话定位：

> 给隐私敏感的个人研究者与小团队的自托管录音知识库：上传或网页录音，自动得到带说话人与时间戳的转写、AI 纪要、观点树与思维导图、章节、带引用的问答；数据留在自己的服务器上，AI 服务可插拔，没网也能演示。

### 1.4 范围边界（v0.1）

| 做 | 不做（列入 Roadmap） |
|---|---|
| 文件上传（音视频 9 种格式）+ 浏览器录音 | 实时转写/实时字幕 |
| 转写、说话人重命名、文本编辑、四种格式导出 | 视频画面理解、PPT 抽取 |
| AI 纪要、观点树、思维导图、章节、洞察、待办、关键词 | 团队协作、评论、@、细粒度权限 |
| 基于转写+纪要的 RAG 问答（SSE，带时间戳引用） | 公开分享链接、移动 App、浏览器扩展 |
| 资料库、标签、全局搜索、统计 | consume 目录/邮件自动导入 |
| Provider 可插拔（DashScope / OpenAI 兼容 / Mock） | 向量数据库服务（pgvector/Qdrant） |
| 单容器 Docker、SQLite、演示模式 | 审计日志、OAuth/LDAP、多租户 |

## 2. 目标用户与典型场景

### 2.1 用户画像

| 画像 | 形态 | 典型一天 | 核心痛点 | 关键需求 | 成功信号 |
|---|---|---|---|---|---|
| **个人研究者** | 1 人；博士生、独立研究员、咨询顾问；有 NAS/旧笔记本 | 上午组会 90 分钟，下午访谈 60 分钟，晚上写论文 | 访谈内容敏感不能上云；重听成本高；需要原话引用与观点脉络 | 本地部署、便宜、观点树、时间戳引用、Markdown/SRT 导出 | 会后 10 分钟内找到“谁承诺了什么”，写作用引用一键跳转 |
| **小团队** | 3–20 人；初创、项目组、设计/咨询工作室；无专职 IT | 周会、客户通话、评审会；录音散落在个人手机和网盘 | 知识随人走；新人上手靠问人；找不到历史决策 | 一条命令部署、共享实例（v0.1 单管理员，P1 多用户）、全局搜索、标签、待办 | 新人 1 分钟内搜到半年前的决策与原话 |
| **隐私敏感组织** | 50+ 人；法务、医疗、教育、政企、安全研究 | 合规访谈、病例讨论、内部评审；内网隔离 | 数据出境/上云审批困难；供应商锁定；审计要求（P2） | 完全自托管、密钥加密、内网模型、可备份、可删除 | 安全评审通过；断网可运行；数据可随卷迁移 |

**非目标用户（v0.1 明确不服务）**：需要实时字幕的直播团队、需要跨组织协作的大型企业会议部门、需要电话系统集成的呼叫中心。

### 2.2 典型场景

| 编号 | 场景 | 触发 | 关键步骤 | 当前替代方案的不足 | Echoic 的期望体验 |
|---|---|---|---|---|---|
| S1 | 组会复盘 | 每周组会结束 | 上传录音 → 等 5 分钟 → 看纪要与章节 → 定位到“交付节点” | 录音存网盘；手动记笔记遗漏 | 打开详情页先看 5 条结论，再点时间戳回听原话 |
| S2 | 客户通话待办 | 销售/顾问通话结束 | 上传 → 看“待办事项” → 复制给团队 | 靠记忆或回听；待办散落聊天 | 待办列表带负责人/时间（若原文提及），可复制导出 |
| S3 | 用户访谈编码 | 访谈录音积累到 10+ 条 | 转写 → 观点树 → 搜索关键词 → 引用原话 | 手工转写昂贵；编码工具割裂 | 观点树按主题聚合，引用带 `[mm:ss]` 与说话人 |
| S4 | 内网演示/培训 | 无外网、无 API Key | 启动容器 → 打开演示数据 → 走完问答 | SaaS 无法离线演示；自建方案门槛高 | 演示模式全流程可点，页面明确标注“示例数据” |
| S5 | 个人语音备忘 | 走路/开车时录一段想法 | 网页录音 → 自动处理 → 搜索/问答 | 手机备忘录不结构化 | 录完即入队（处理时长另计），次日可搜到 |

### 3.2 P0 用户故事与验收标准

| ID | 用户故事 | 验收标准（可执行） |
|---|---|---|
| US-01 | 作为管理员，我能用账号密码登录，并确信会话安全 | 正确凭据进入资料库；错误凭据统一提示且 5 次/分钟/IP 限流；Cookie 为 HttpOnly；退出后受保护接口 401 |
| US-02 | 作为用户，我能拖拽上传音视频并看到处理进度 | 9 种格式可传，≤2GB；非法类型 415、超限 413；上传后状态 `queued`，详情页 2s 轮询展示 stage/progress |
| US-03 | 作为用户，我能直接在浏览器录音并保存 | Chrome/Edge 授权后可录、暂停、继续、重录；保存后 `source=browser_recording`，时长与录音一致 |
| US-04 | 作为用户，我能得到带说话人和时间戳的转写 | 每段含 speaker、start_ms、end_ms、text；可改说话人名与文本并持久化；当前播放段高亮并自动滚动 |
| US-05 | 作为用户，我能读到结构化中文纪要 | Markdown 含概述/关键结论/决议/待办；人名与数字来自原文；可单类重新生成 |
| US-06 | 作为用户，我能从观点树看到论证结构 | 2–3 层、12–40 节点；`topic/point/task/risk` 有区分；点击节点跳转到对应时间 |
| US-07 | 作为用户，我能打开思维导图总览全局 | 全屏弹窗、可缩放拖拽、fitView；节点按类型着色；点击节点 seek 并关闭弹窗 |
| US-08 | 作为用户，我能按章节快速跳转 | 3–12 章，时间升序不重叠；显示标题、区间、摘要、bullets；当前章高亮 |
| US-09 | 作为用户，我能就这场录音提问并获得带引用的回答 | SSE 依次收到 start/delta/citations/done；引用 `[mm:ss]` 可点击 seek；无依据时明确说“转录稿中没有提到” |
| US-10 | 作为用户，我能搜索全部录音与转写片段 | 标题/描述/全文命中；片段结果带录音名、说话人、时间点；点击进入详情并 seek |
| US-11 | 作为用户，我能把转写导出给外部工具 | TXT/SRT/Markdown/JSON 四种格式；文件名 UTF-8 正确；内容与页面一致 |
| US-12 | 作为评估者，我在没有任何 Key 时也能跑通全流程 | `ECHOIC_DEMO_SEED=1` 自动生成示例；上传任意音频由 mock 生成演示转写；页面顶部有演示模式提示 |

## 4. 需求清单（P0 / P1 / P2）

### 4.1 优先级口径

- **P0（v0.1 必达）**：缺少任一条，演示闭环不成立或安全底线失守。
- **P1（v0.2 近期）**：显著提升复用与协作价值，但不阻塞 v0.1。
- **P2（v1.0 及以后）**：平台化/规模化能力，需架构演进（向量库、对象存储、权限模型）。

### 4.2 P0 需求

| ID | 需求 | 验收标准 | 对应能力 |
|---|---|---|---|
| R-01 | 登录、退出、改密、会话保持 | bcrypt 校验；JWT 7 天；HttpOnly/SameSite=Lax；401 跳登录；限速生效 | G10 |
| R-02 | 文件上传（音视频） | 扩展名 + ffprobe 双重校验；≤2048MB；落盘为 uuid 目录；入队 | G1/G2 |
| R-03 | 浏览器录音 | MediaRecorder；计时/暂停/重录/设备选择；权限失败有 HTTPS 提示 | G1 |

| R-07 | 观点树 | 结构化 JSON；主题/观点/任务/风险；时间戳可跳转 | G5 |

### 4.5 依赖与裁剪原则

- P0 的**关键路径**：`R-02/R-04 → R-05 → R-06/R-07/R-09 → R-10 → R-11`。观点树与思维导图共用一次分析结果，不能各自调用一次 LLM。
- 当排期不足时，**优先砍 R-08（思维导图可视化）而不是 R-07（观点树数据）**：数据在，后续补图成本低；数据不在，页面无内容。
- 当 ASR 供应商不可用时，**保留 Mock 路径与错误提示**，不能把“处理中”卡死；这是演示与测试的底线。
- 任何 P1/P2 需求不得引入对 Redis/Celery/Postgres 的**强制**依赖，保持单容器可运行。

## 5. 竞品分析

### 5.1 对比对象与方法

选取 5 个参照物：**paperless-ngx**（自托管资料库范式）、**飞书妙记**（会议转写体验基准）、**钉钉闪记/AI 听记**（组织内会议记录）、**通义听悟**（转写与结构化能力）、**NotebookLM（Google 站点现以 Gemini Notebook 呈现）**（来源锚定问答范式）。

方法：只采信官方产品页/官方文档的公开描述；无法确认的能力标 `?`；价格只描述计费形态，不写具体数字，避免过期误导。

### 5.2 形态与商业对比

| 产品 | 部署形态 | 数据主权 | 分享/协作 | 价格形态 | 开放性 |
|---|---|---|---|---|---|
| **paperless-ngx** | 自托管：Docker Compose/裸机 | 数据本地存储；可选远程 OCR/LLM 需显式开启；官方明确“不应部署在不可信主机”，数据明文存储 | 多用户权限、公开链接（可设过期） | 开源免费，自付硬件与运维 | 开源、REST API、工作流/消费目录可扩展 |
| **飞书妙记** | SaaS（飞书云） | 数据在飞书云；大型企业可选专属/私有化，非自助 | 链接分享、评论、@、片段，与飞书生态集成 | 随飞书套餐按人订阅，有免费版/试用 | 开放平台 API 存在，但妙记数据与二次开发受生态约束 |

### 5.4 竞品要点与可借鉴之处

- **paperless-ngx**：验证了“自托管 + 资料库 + 消费管线 + 标签”的长期生命力。可借鉴：consume 目录、公开链接、权限模型、备份叙事；但其文档模型与会议时间轴天然不同，Echoic 不能照搬。
- **飞书妙记**：体验上可借鉴播放器卡片、四 Tab、右侧 AI 面板与猜你想问等信息架构。可借鉴：低摩擦分享、转写内搜索、评论；不借鉴：强绑定办公套件、云端假设。
- **钉钉闪记/AI 听记**：强在组织内分发与待办闭环。可借鉴：待办与消息/日程的连接（P2）；不借鉴：以组织账号体系为前提。
- **通义听悟**：转写质量、章节速览、翻译、思维导图是直接对标项；其 API 也说明“能力可被集成”。Echoic 的差异是把能力装进用户自己的服务器，并允许换模型。
- **NotebookLM**：把“回答必须锚定来源”做成了产品原则。Echoic 的 citations 设计应坚持“无来源不下结论”，并在 UI 上让引用可点击回听。

### 5.5 SWOT

| | 有利 | 不利 |
|---|---|---|
| **内部** | **S1** 数据主权与隐私叙事清晰，与云服务形成结构性差异<br>**S2** 转写→纪要→观点树→导图→章节→问答的一体化闭环<br>**S3** 单容器 + SQLite + 内嵌 worker，运维成本极低<br>**S4** Provider 可插拔 + Mock，离线可演示、可测试<br>**S5** 开源与 REST API，易被集成与审计 | **W1** 无实时转写、无协作/分享，体验上落后 SaaS<br>**W2** 转写与纪要质量受第三方模型制约<br>**W3** 单人/小团队维护，品牌与生态尚新<br>**W4** SQLite + 单 worker 的规模上限明确<br>**W5** 前端完成度与视觉细节仍需打磨 |
| **外部** | **O1** 隐私合规与“数据不出内网”需求上升<br>**O2** 本地/内网 LLM（Ollama、vLLM）成熟，替代成本下降<br>**O3** paperless-ngx 用户群对“自托管资料库”有认知基础<br>**O4** ASR/LLM 单价长期下降，个人可负担<br>**O5** 研究与教育场景需要可引用的访谈知识库 | **T1** 飞书/钉钉免费捆绑，获客成本高<br>**T2** 通义听悟 API 便宜且能力强，可能被直接集成<br>**T3** NotebookLM 免费且问答体验优秀<br>**T4** 供应商接口/配额/合规政策变化<br>**T5** 用户把“会议助手”预期带到“事后知识库”上 |

### 5.6 差异化结论

1. **不打“会议协作”，打“录音主权 + 事后知识化”。** 与飞书/钉钉正面竞争协作是劣势；Echoic 的战场是“录完之后，知识归谁、能不能被检索与引用”。
2. **少有的同时满足三件事的开源方案**：完全自托管、完整 AI 闭环（含观点树/思维导图/章节/引用问答）、无 Key 可演示。前两者竞品各占一半，三者同时具备的很少。
3. **护城河不在模型，在数据与工作流**：Provider 可替换意味着模型不是壁垒；壁垒是“用户的历史录音 + 结构化观点 + 标签 + 引用关系”留在本地，以及可审计、可迁移、可二次开发。
4. **明确承认短板**：v0.1 不拼实时、不拼协作、不拼移动端；这些放进 Roadmap，而不是用模糊话术掩盖。
