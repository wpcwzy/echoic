## 2. R-19 实时转写与实时字幕

**目标**：麦克风 100 ms PCM 帧经后端中转到 DashScope `paraformer-realtime-v2`，增量字幕 P50 < 2 s；final 句落库；停止后与现有上传/离线管线衔接；断网/切后台/后端重启可恢复；Mock 离线可演示。**非目标**：实时说话人分离（该模型无 `speaker_id`）、翻译、多轨、实时编辑/AI 纪要。

**端到端**：

```
浏览器 ├─ MediaRecorder（webm/mp4，停止后上传）
      └─ AudioWorklet：Float32→16k/mono/Int16，100ms=3200B
           │ WS 二进制帧（同源 Cookie）
FastAPI /api/live/sessions/{uuid}/stream（双工）
  ├─ LiveSessionManager（进程内，单生产者）
  ├─ live_segments 落库（只落 final）
  ├─ 事件推回（partial/final/error）+ SSE 旁路
  └─ websockets ──► DashScope paraformer-realtime-v2
停止：Blob 上传 → POST /api/recordings/upload → POST /api/live/sessions/{uuid}/stop
     → merge_mode=replace（离线重转写，含说话人）| promote（提升实时稿，跳过 ASR）
```

**浏览器采集**：`MediaRecorder` 分片是容器格式，不能直接喂实时接口；用**同一 `MediaStream` 双采集**。Worklet 按实际 `ctx.sampleRate` 重采样，固定 3200 B/帧；服务端按字节数推算时间轴，不信客户端时间戳。Safari 采样率不跟随构造参数、非安全上下文无 Worklet，需探测并禁用开关。客户端缓冲 30 s，`bufferedAmount>256KB` 暂停发送；重连从 `audio_sent_ms` 续传。

```ts
const ctx = new AudioContext(); await ctx.audioWorklet.addModule('/worklets/pcm16k.js');
const node = new AudioWorkletNode(ctx, 'pcm16k', { processorOptions: { targetRate: 16000, frameMs: 100 }});
node.port.onmessage = (e: MessageEvent<ArrayBuffer>) => ws.send(e.data); // 3200 B
ctx.createMediaStreamSource(stream).connect(node); // 不连 destination
```

**后端会话管理**：`LiveSessionManager` 持有 `asyncio.Queue(maxsize=100)`（约 10 s）、provider task、订阅者、`total_audio_ms/task_base_ms/last_seq`；同一 session 只允许一个音频生产者（第二个 close `4409`，只读走 SSE）。上游时间戳是当前 task 的相对时间，`start_ms = task_base_ms + begin_time`；重连缺口 ≤30 s 补静音帧，超过则记 `asr.gap` 并推进基准。上游断连自动重连（新 `task_id`，1/2/4 s 退避，最多 3 次）；连续 25 分钟在句末主动滚动重连；队列满先暂停读 WS 2 s，仍满 close `4413`，客户端带缓冲重连，**不静默丢帧**。

```python
if s.get("heartbeat"): return
start = runtime.task_base_ms + int(s["begin_time"]); end = runtime.task_base_ms + int(s["end_time"])
if not s["sentence_end"]:
    await runtime.broadcast({"type":"asr.partial","seq":runtime.next_seq(),"start_ms":start,"end_ms":end,
                             "text":s["text"],"revision":runtime.partial_revision})
else:
    seg = save_live_segment(runtime.session_id, start, end, s["text"])  # DB commit
    await runtime.broadcast({"type":"asr.final","seq":seg.seq,"segment_id":seg.id,
                             "start_ms":start,"end_ms":end,"text":seg.text})
```

**DashScope 协议**：建连 `wss://dashscope.aliyuncs.com/api-ws/v1/inference`，握手头 Bearer；`run-task`（`task_group=audio`、`task=asr`、`function=recognition`、`model=paraformer-realtime-v2`、`format=pcm`、`sample_rate=16000`、`language_hints`、`semantic_punctuation_enabled=true`）→ `task-started` → 持续二进制音频 → `result-generated`（`sentence.begin_time/end_time/text/sentence_end/heartbeat`）→ `finish-task` → `task-finished`。`sentence_end=false` 覆盖 UI 最后一行，`true` 才落库；`heartbeat=true` 丢弃；`task-failed` 关闭连接不可复用；任务结束 60 s 空闲断开；无 `speaker_id`。

**数据模型**：`live_sessions(id, uuid unique, owner_id, recording_id nullable, status, provider, model, language, sample_rate, channels, audio_bytes, audio_ms, last_seq, title, error_message, started_at, ended_at, last_activity_at)`，status 为 `starting/active/stopping/completed/failed/abandoned`；`live_segments(id, session_id FK cascade, seq, start_ms, end_ms, text, is_final, revision, provider_begin_ms, created_at)`，唯一 `(session_id,seq)`，索引 `(session_id,start_ms)`。partial 只在内存/广播，final 每句一次短事务；会话保留 7 天供对照。

**API 草案**：`POST /api/live/sessions {language?,title?,model?,recording_id?}` → `201 {id,uuid,ws_url,events_url,sample_rate,format,ws_ticket?,expires_at,max_duration_ms}`；`WS /api/live/sessions/{uuid}/stream`（Cookie + Origin，非浏览器用 60 s 一次性 ticket）；`GET .../{uuid}` 状态；`GET .../transcript?after_seq=` 补拉；`GET .../events?after_seq=` SSE 只读；`POST .../stop {recording_id?}`；`POST .../attach`；`DELETE ...` 放弃。关闭码 `4401/4404/4409/4413/4500`。事件示例：

```json
{"type":"session.started","seq":1,"sample_rate":16000,"format":"pcm_s16le"}
{"type":"asr.partial","seq":12,"start_ms":18400,"end_ms":20100,"text":"我们先看第一页","revision":3}
{"type":"asr.final","seq":13,"segment_id":87,"start_ms":18400,"end_ms":20950,"text":"我们先看第一页。"}
{"type":"error","seq":14,"code":"PROVIDER_ERROR","message":"实时服务连接中断，正在重连","fatal":false}
```

SSE 用 `event: asr.final` + `id: seq` + `data: {...}`，支持 `Last-Event-ID` 重放；双方每 15 s 心跳，45 s 无消息重连：

```
event: asr.final
id: 13
data: {"type":"asr.final","segment_id":87,"start_ms":18400,"end_ms":20950,"text":"我们先看第一页。"}
```

**Mock**：`LiveASRProvider` 协议（`open/send/finish/events`），注册表 `build_live_asr_provider` 支持 `mock|dashscope_realtime`，`openai/dashscope_file` 明确报不支持。Mock 读 `demo_data.json` 的 segments，按 `ECHOIC_LIVE_MOCK_SPEED`（默认 8，测试 64）吐 partial/final，不联网；`TestClient.websocket_connect` 灌二进制帧即可测。

**停止后的合并**：不做文本级去重——实时稿（无说话人）与离线稿（有说话人）是两次识别，逐字对齐成本高收益低，采用**离线优先 + 实时兜底**：

| merge_mode | 条件 | 行为 |
|---|---|---|
| `replace`（默认） | 配置了支持文件/说话人的离线 ASR | 正常 `process(from="all")`，离线替换转录；实时稿留档，详情页标注“已校正” |
| `promote` | 无离线 ASR、离线失败、用户选快速模式 | final 片段写 `transcript_segments`（单 speaker“说话人1”），`asr_provider='live:paraformer-realtime-v2'`，再 `process(from="insights")` 跳过 ASR 只做分析/embedding |
| `keep_live` | 用户显式选择 | 同 promote，但离线结果不覆盖（实时稿已人工校对） |

```python
if merge_mode == "replace" and offline_asr_available(cfg): enqueue(rec.id, "all")
else: promote_live_segments(session, rec); enqueue(rec.id, "insights")
```

`replace` 失败且实时稿完整时自动 `promote` 并再入队 insights，避免“录完什么都没有”（最多一次）。实时过程不调用 LLM，分析只跑一次；`recorded_at=session.started_at`，时间轴从 0 对齐；同一录音只允许一个 replace 会话，重复 stop 幂等。**成本**：实时 + 离线双份 ASR，按文档 `paraformer-v2` 0.00008 元/秒示例约 0.29 元/小时/次，双跑约 0.58 元/小时（实时单价/免费额度待核实）；只配实时时自动 promote。

**生命周期与限制**：`starting→active→stopping→completed`，任意态可 failed；无 WS 且无 stop 120 s → abandoned；`last_activity_at` 超 2 h 清理；单用户 1 个 active、全实例默认 2 个；`ECHOIC_LIVE_MAX_MINUTES=180`，超限自动 stop 且音频仍可上传；后端重启后客户端带 `resume=1` 续传，final 不丢、partial 丢失可接受；不支持多 API worker；音频只在内存/供应商 WS，不落盘，日志不记文本。

**前端**：录音页“实时字幕（Beta）”开关；右侧字幕面板 partial 用次要色 + 光标、final 正常色，自动滚底（用户上滚暂停并显示“回到最新”）；状态点“连接中/转写中/重连中/已中断”；停止先停 MediaRecorder 拿完整 Blob → 上传 → `stop {recording_id}`，上传失败仍 stop 并保留会话；详情页处理中只读展示实时稿 + 黄条“完成后替换为带说话人的离线转写”，完成后消失；移动端字幕改底部抽屉，切后台回前台补拉 `after_seq`。

**测试**：单元测帧长/重采样/offset/状态机；TestClient WS 灌 10 帧收 started+final，第二连接 4409，SSE 重放；merge 三种模式与失败回退；Playwright 假麦克风 20 s 全流程 + 断网 5 s；手工 Chrome/Edge/Safari、蓝牙麦、1 小时长会话、双标签只允许一个生产者。

**分阶段**：M1（3 d）模型 + WS 回声/Mock + 字幕 UI；M2（4 d）DashScope 适配 + 重连/offset + 落库 + SSE；M3（3 d）stop/merge/promote + 详情状态 + 成本开关 + E2E，发布 Beta 默认关闭。

## 3. R-20 向量检索（pgvector / sqlite-vec）

**现状局限**：聊天把单录音全部 chunk 读入 Python 逐条 `np.frombuffer` 算余弦，O(N) 且在事件循环内；全局搜索只有 `LIKE`；无 `embedding_model`，换模型/维度后旧向量仍参与计算、维度不同静默 0 分；无重建入口。按 5000 条录音 × 约 40 chunk ≈ **20 万向量**，1024 维 float32 约 800 MB，不可能每次全量载入。**单录音 RAG 用 numpy 足够，真正需要 ANN 的是全局检索与超大单录音。**

**统一抽象**：

```python
@dataclass(frozen=True)
class VectorRecord: chunk_id:int; recording_id:int; idx:int; start_ms:int; end_ms:int; vector:list[float]; model:str; dim:int
class VectorStore(Protocol):
    backend: str
    def upsert(self, records: Sequence[VectorRecord]) -> None: ...
    def delete_recording(self, recording_id: int) -> int: ...
    def search(self, query: Sequence[float], *, top_k: int = 40,
               recording_ids: Sequence[int] | None = None, min_score: float = 0.0) -> list[VectorHit]: ...
    def stats(self) -> VectorStoreStats: ...
    def health(self) -> tuple[bool, str]: ...
```

方法同步，async 调用点用 `asyncio.to_thread`；向量写入前 L2 归一化，`VectorHit.score` 统一余弦相似度。`VectorHit=(chunk_id, recording_id, score, start_ms, end_ms)`。

**方案 A：pgvector（PG profile）**：镜像换 `pgvector/pgvector:pg16`；启动 `CREATE EXTENSION IF NOT EXISTS vector`，无权限记 warning 并降级，不阻断启动。独立表而非给 chunks 加列（SQLite 不识别 vector 类型，且便于整表重建；`chunks.embedding` 保留为可移植副本）：

```sql
CREATE TABLE chunk_vectors (
 chunk_id BIGINT PRIMARY KEY REFERENCES chunks(id) ON DELETE CASCADE,
 recording_id BIGINT NOT NULL REFERENCES recordings(id) ON DELETE CASCADE,
 idx INT NOT NULL, start_ms BIGINT NOT NULL, end_ms BIGINT NOT NULL,
 embedding vector(1024) NOT NULL, model VARCHAR(120) NOT NULL, dim INT NOT NULL,
 created_at TIMESTAMPTZ NOT NULL DEFAULT now());
CREATE INDEX ix_cv_recording ON chunk_vectors(recording_id);
CREATE INDEX ix_cv_hnsw ON chunk_vectors USING hnsw (embedding vector_cosine_ops) WITH (m=16, ef_construction=64);
SET LOCAL hnsw.ef_search=100;
SELECT chunk_id, recording_id, start_ms, end_ms, 1-(embedding <=> :q) AS score
FROM chunk_vectors WHERE model=:model AND dim=:dim ORDER BY embedding <=> :q LIMIT :k;
```

HNSW 对 `vector` 上限 2000 维；`text-embedding-v3` 默认 1024 可用，2560 维模型必须改 `halfvec` 或降维，配置校验直接拒绝。ACL：先取 `accessible_recording_ids`，过滤会掉召回，采用 **oversample 4× 后过滤**，不足再补；pgvector 0.8 的 `hnsw.iterative_scan` 可用则开（版本相关）。代价是向量存两份（约 4 KB/chunk，20 万约 800 MB），可配 `ECHOIC_VECTOR_KEEP_BLOB=false` 停写 BLOB。

**方案 B：SQLite（sqlite-vec / numpy）**：

```sql
CREATE VIRTUAL TABLE chunk_vectors USING vec0(
 chunk_id INTEGER PRIMARY KEY, embedding float[1024] distance_metric=cosine, recording_id INTEGER,
 +idx INTEGER, +start_ms INTEGER, +end_ms INTEGER, +model TEXT);
SELECT chunk_id, recording_id, start_ms, end_ms, distance
FROM chunk_vectors WHERE embedding MATCH :q AND k=:k ORDER BY distance;
```

Python 侧 `sqlite_vec.load(conn)` 前需 `enable_load_extension(True)`；`python:3.12-slim` 是否支持扩展加载**必须在 CI/镜像实测**，失败自动退回 numpy。vec0 元数据过滤语法在 0.x 有变化，适配器先 KNN 后过滤/oversample，写入 batch 200。numpy 兜底改为“当前 model/dim 的归一化矩阵缓存 + 一次矩阵乘 + argpartition”，key 为 `(model,dim,index_version)`，写操作递增版本。阈值：**<2 万 chunk 用 numpy（<80 MB、<30 ms）；2 万–20 万优先 sqlite-vec；>20 万或多实例用 pgvector/外部**。

**方案 C：外部向量库（仅预留）**：Qdrant/Milvus 只在“多实例 + 百万级 + 独立扩缩容”时值得引入，会新增常驻服务，违反单容器默认。只保留 `ECHOIC_VECTOR_BACKEND=qdrant` 配置位与适配点，v0.3 不实现；若实现，`QdrantVectorStore` 复用同一接口：collection `echoic_chunks`、point id=`chunk_id`、payload `{recording_id,idx,start_ms,end_ms,model}`，查询 `query_points` 时按 `model/dim + recording_id any` 过滤，配置 `ECHOIC_QDRANT_URL/API_KEY/COLLECTION`，本地 BLOB 仍保留作回退；未来作为可选 compose profile。

**混合检索**：向量 top 40（全局 `min_score=0.2`，聊天不设硬阈值）+ 字面 top 40（沿用 CJK 二元组/英文 token + IDF），用 RRF 融合（对量纲不敏感）：

```python
def rrf(vec_rank, lex_rank, k=60, w_vec=1.0, w_lex=0.8):
    s = defaultdict(float)
    for i, cid in enumerate(vec_rank): s[cid] += w_vec / (k + i + 1)
    for i, cid in enumerate(lex_rank): s[cid] += w_lex / (k + i + 1)
    return sorted(s.items(), key=lambda kv: kv[1], reverse=True)
```

聊天取融合 top 8，沿用现有上下文预算（纪要 1500 + 章节 2500 + 片段 ≤14000 字符）与 citation 逻辑；全局 `GET /api/search?q=&mode=hybrid|literal|semantic&limit=20`，响应加 `recordings[].score`、`segments[].score/match`、`mode_used`，按录音聚合、每录音最多 3 条；无索引自动降 literal。BM25 作为 Phase 2：新增 `chunks.search_text`（CJK 二元组空格拼接），SQLite FTS5 `unicode61`+`bm25()`、PG `to_tsvector('simple')`+GIN+`ts_rank_cd`；不要把 FTS5 trigram 当中文分词器。ACL：numpy/sqlite 先 mask 再排序，pgvector oversample 后过滤，有效结果 <top_k/2 再放大 2× 重查。

**迁移与降级**：启动加列与元数据；工厂按 `DATABASE_URL` + `ECHOIC_VECTOR_BACKEND=auto|numpy|sqlite_vec|pgvector` 选择，auto 顺序 PG+扩展 → sqlite-vec → numpy；首次启用后台从 BLOB 回填（不重新调 embedding），只回填 model/dim 匹配的向量，其余 stale；双写期查询优先 store、不可用回退 numpy BLOB、再退字面；health 增 `vector: ok|degraded|stale`。

## 4. R-21 对象存储（S3 / MinIO）

**现状耦合**：`storage.py` 的 `recording_dir/original_path/playback_path/asr_wav_path/save_upload/delete_recording_dir` 全是本地 Path；`_pick_media` 返回 `Path` 给 `_serve_file`；`pipeline._prepare` 直接读写目录；`demo.py` 直接 `shutil.copyfile`；consume 很可能直接移动文件。必须先解耦“逻辑 key”与“物理存储”。

**抽象**：

```python
class StorageBackend(Protocol):
    name: str
    def put_file(self, key: str, src: Path, *, content_type: str | None = None) -> ObjectMeta: ...
    def put_stream(self, key: str, stream: BinaryIO, *, size: int | None, content_type: str | None = None) -> ObjectMeta: ...
    def open_range(self, key: str, start: int = 0, end: int | None = None) -> Iterator[bytes]: ...
    def stat(self, key: str) -> ObjectMeta | None: ...
    def delete(self, key: str) -> None: ...
    def delete_prefix(self, prefix: str) -> int: ...
    def exists(self, key: str) -> bool: ...
    def local_path(self, key: str) -> Path | None: ...  # 仅 local
    def presign_get(self, key: str, *, expires_s: int, filename: str | None, inline: bool) -> str | None: ...
```

key 规范 `media/{uuid}/original{ext}|playback.m4a|asr.wav`，`storage_dir` 仍是逻辑前缀 `media/{uuid}`，不改旧值；新增 `recordings.storage_backend VARCHAR(16) DEFAULT 'local'` 支持逐条混合/回滚。`LocalStorageBackend` 复用现有路径越界校验；`S3StorageBackend` 用 boto3 + `endpoint_url` + path-style 兼容 MinIO，key 可加 `ECHOIC_S3_PREFIX`。

**读取：代理 vs 签名 URL**：

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| 同源代理 | 复用 Cookie、隐藏 bucket、无 CORS/公网要求、可审计 | API 承担带宽，需正确 206/416 | **默认** |
| 307 到 presigned | 卸载带宽、S3 原生 Range | 浏览器须能访问 S3/MinIO；URL 泄露即临时公开；每次 Range 重签；内网常不可达 | opt-in `ECHOIC_MEDIA_DELIVERY=redirect` |

代理：解析 `Range` → `stat` 取 size → `open_range` 流式 `StreamingResponse(206)`，带 `Content-Range/Accept-Ranges/Content-Length/ETag/Content-Disposition`（RFC 5987），越界 416；S3 用 `get_object(Range=...)` 按 256 KB 迭代，禁止整对象入内存。307：presign 默认 300 s，`download=1` 用 `response-content-disposition`，URL 不写日志；Safari 对 307+Range 行为待实测，默认关闭。缓存头 `private, max-age=0, must-revalidate`。

**上传**：始终先落 `data/tmp/upload-{uuid}`（ffprobe 需要本地文件），`save_upload` 边写边计数超限 413；探测通过后 local 原子 `rename`，S3 `put_file` 后删临时文件，避免“先传 S3 再发现格式不支持”的垃圾对象。multipart 阈值 16 MB、分片 8–16 MB，失败 abort；磁盘不足返回 `507 INSUFFICIENT_STORAGE` 并在 health 暴露 free bytes；删除一律 `delete_prefix`，S3 失败不静默，记录供重试。

**配置**：`ECHOIC_STORAGE_BACKEND=local|s3`、`ECHOIC_S3_ENDPOINT`（空=AWS）、`ECHOIC_S3_BUCKET=echoic`、`ECHOIC_S3_ACCESS_KEY_ID/_SECRET_ACCESS_KEY`（仅环境变量，空则 IAM Role）、`ECHOIC_S3_REGION=us-east-1`、`ECHOIC_S3_PATH_STYLE=true`、`ECHOIC_S3_VERIFY_TLS=true`、`ECHOIC_S3_CA_BUNDLE`、`ECHOIC_S3_PREFIX=echoic/`、`ECHOIC_MEDIA_DELIVERY=proxy|redirect`、`ECHOIC_S3_PRESIGN_EXPIRES=300`、`ECHOIC_TMP_DIR=<data>/tmp`。凭据不进 `app_settings`；设置页只显示 bucket/endpoint/已配置状态 + 测试连接。

**备份/迁移**：`python -m app.tools.storage_migrate --from local --to s3 --dry-run/--apply/--verify-only/--rollback`；复制后校验大小 + sha256（multipart ETag ≠ MD5，不能当校验和），逐条更新 `storage_backend`；默认不删源，显式 `--prune-source`；混合状态可读，按 key 存在 + 校验续跑。备份叙事：local=备份 data 卷；S3=桶版本化 + 生命周期 + DB 备份；恢复先 DB 后媒体。

**demo/consume**：`generate_tone_audio` 写临时文件后 `put_file`，S3 不可用降级为“无音频演示数据”并 warning，不阻断启动；consume 必须 `put_stream`，禁止 `shutil.move` 进 `data/media`，继续用 `imported_files.sha256` 去重（batch 1 已实现）。

**测试**：`moto[s3]` 覆盖 put/open_range/delete_prefix/presign、200/206/416、下载名、413、删除幂等；local/S3 契约参数化；迁移 dry-run 不写、apply 后可读、校验失败不改 backend；MinIO 作为 CI 可选 job（`minio/minio` service）；回归 demo/consume/上传→播放→删除在 local 与 moto 各一次；新增 `docker compose --profile minio` 冒烟。

## 5. R-23 回收站与批量操作

**语义**：删除=软删除，设 `deleted_at`，保留媒体与全部派生数据，可恢复；彻底删除才移除文件与 DB 行。默认保留 30 天（`system.trash_retention_days`，1–365），到期维护任务清理；管理员可立即彻底删除/清空。列表、搜索、仪表盘、统计、分享、问答、媒体默认都 404；回收站接口可见。**不要**把 `status` 改成 `trashed`（破坏状态机/恢复展示），`trashed` 只作 API 派生字段。

**查询过滤**：统一全局条件，避免 26 处查询漏改：

```python
@event.listens_for(Session, "do_orm_execute")
def _exclude_trashed(state):
    if state.is_select and not state.execution_options.get("include_deleted"):
        state.statement = state.statement.options(
            with_loader_criteria(Recording, Recording.deleted_at.is_(None), include_aliases=True))
```

回收站/恢复显式 `execution_options(include_deleted=True)`；后台任务默认也过滤，彻底删除显式包含。**坑位**：batch 1 的 `get_recording_for_user` 用 `db.get(Recording,id)`，不走 ORM 查询选项，必须改成 `db.scalars(select(...))` 并默认排除 `deleted_at`；`select(func.count()).select_from(Recording)` 无实体，统计函数要显式加 `deleted_at IS NULL`；与 `recording_scope(query,user)` 组合时，软删条件只放全局事件或只放 scope，避免重复/遗漏。两类都加专项测试。媒体/详情对已删录音返回 404，不泄露存在性。

**API 草案**：`DELETE /api/recordings/{id}` 软删（处理中先取消 job）→ `{ok,deleted_at,purge_after}`；`DELETE ...?purge=true` 管理员立即彻底删；`POST /api/recordings/{id}/restore`（过期/文件缺失 → `409 MEDIA_MISSING`/`410 TRASH_EXPIRED`）；`GET /api/trash/recordings?query=&page=&page_size=` → `{items,total,stats:{count,bytes,retention_days}}`；`POST /api/trash/empty` 管理员异步清空。

**保留期清理**：新增 `maintenance_tasks(id,kind,status,progress,total,payload_json,error,created_at/started_at/finished_at)`，不复用 `jobs.recording_id` 非空约束；worker 每 60 s 轮询，与录音任务串行避免 SQLite 写竞争。`trash_purge` 每天一次/启动后延迟 5 分钟，选 `deleted_at < now-retention` 且 `purge_started_at IS NULL`：

```python

storage.delete_prefix(rec.storage_dir)      # 先文件，幂等
vector_store.delete_recording(rec.id)       # 失败只记日志
```

### 7.6 与单容器约束的兼容性

| 能力 | 默认（单容器/SQLite/无 Redis） | 可选增强 | 不得成为前提 |
|---|---|---|---|
| 实时 | 进程内 manager + DB；单 API 进程 | 独立 worker 不影响 WS | Redis/pub-sub、多副本 |
| 向量 | numpy 矩阵化；sqlite-vec 可用则启用 | PG+pgvector；未来 Qdrant | 外部向量库必装 |
| 对象存储 | local，行为同 v0.1 | S3/MinIO profile | 必须有 S3 |
| 回收站清理 | `maintenance_tasks` + worker 轮询 | 外部 cron 调 CLI | Celery/Beat |
| 暗色 | 纯前端 | 账号偏好同步 | 服务端渲染 |
| 迁移 | 启动幂等迁移 | 手动 CLI 备份 | Alembic/迁移服务 |

**发布/回滚**：v0.2.1 升级前自动复制 SQLite（PG 用 pg_dump）到 `data/backups/pre-0.2.1-<ts>`；kill switch：`ECHOIC_LIVE_ENABLED=false`、`ECHOIC_VECTOR_BACKEND=numpy`、`ECHOIC_STORAGE_BACKEND=local`（旧文件仍在）；存储迁移默认保留源，确认后再 prune。
