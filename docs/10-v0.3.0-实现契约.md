## 0. 公共约束与版本

- 版本 `0.3.0`；默认配置必须保持单容器 / SQLite / 无 Redis 可运行；所有新能力提供 kill switch（`ECHOIC_*`）。
- 启动迁移必须幂等，兼容 v0.1/v0.2 数据目录；SQLite 与 PostgreSQL 都适用。
- 软删除（trash）是新全局约束：**所有对录音的查询/读取/媒体/分享/搜索/聊天/统计默认必须排除 `deleted_at IS NOT NULL`**；只有回收站列表、恢复、彻底删除例外。
- 权限沿用 R-18：admin 全部；member 仅自己 `owner_id` 的录音（不可见→404）。新增能力不得绕过。
- 单进程部署为前提：实时 WS 与内存限流不支持多副本；文档写明。
- 所有新 API 错误格式保持 `{"detail","code"}`。

## 1. R-23 回收站与批量操作（backend-api + frontend）

### 1.1 API

| 方法 | 路径 | 说明 |
|---|---|---|
| DELETE | `/api/recordings/{id}` | 软删除（owner/admin）→ `{ok:true,id,deleted_at,restore_before}`；已删除 → 404 |
| GET | `/api/recordings?trashed=true` | 回收站列表（admin 全部，member 仅自己），默认按 `deleted_at desc`；`stats` 为该范围统计；items 含 `deleted_at` |
| POST | `/api/recordings/{id}/restore` | 恢复（仅回收站内，owner/admin）→ `RecordingSummary` |
| DELETE | `/api/recordings/{id}/purge` | 彻底删除（仅回收站内，owner/admin）→ `{ok:true,purged:true}`；清理 DB 行 + 媒体/存储前缀 + 分享 |
| POST | `/api/recordings/batch` | 批量操作，见下 |

批量 body：
```json
{"action":"trash|restore|purge|reprocess|tag_add|tag_remove",
 "recording_ids":[1,2,3],
 "tag_ids":[1,2],
 "from":"all|asr|insights|embeddings"}
```
→ `{"action":"trash","succeeded":2,"failed":1,"results":[{"id":1,"ok":true},{"id":2,"ok":true},{"id":3,"ok":false,"error":"录音不存在"}]}`
- 上限 `ECHOIC_BATCH_MAX_ITEMS`（默认 100），超限 400。
- 权限逐条校验（部分成功，不整体回滚）；tag_add/tag_remove 仅 admin；reprocess 仅对未删除录音，member 仅自己。
- 批量删除默认走回收站（不可直接批量 purge）。

### 1.2 软删除不变量（必须逐项验证）

- 列表/搜索/仪表盘/统计/标签计数/分享列表/consume 导入后重复检测均排除已删除。
- `GET /api/recordings/{id}`、media/transcript/insights/chat/history/shares/jobs/live 对已删除 → **404**。
- 已删除录音的公开分享 → **404**；删除后其分享自动软撤销（可恢复时不自动恢复分享；由用户重新创建或恢复后由 owner 手动开启，实现可自行决定并在报告说明）。
- 恢复后转录/分析/标签/分享关系完整可读；彻底删除清理媒体目录/对象与 DB 行（分享级联）。
- worker 每小时调用 `services.trash.purge_expired()`（owner 可写；实现放 backend-api 的 `services/trash.py`），保留期默认 30 天；`ECHOIC_TRASH_RETENTION_DAYS`。

### 1.3 前端

- 资料库：卡片/列表支持多选（checkbox + 全选），底部/顶部批量操作条：移入回收站、打标签、重跑分析、取消；操作结果 toast（部分失败列出原因）；移入回收站后 5s 内可撤销（restore）。
- 视图切换/筛选增加「回收站」入口：显示删除时间、剩余保留天数、恢复/彻底删除（二次确认）；空态说明保留策略。
- 详情页对已删除录音不存在（404 处理）；成员无 admin-only 操作。
- 批量选择需与筛选/分页协同（仅当前页选择，文案写明）。

## 3. R-21 对象存储抽象（backend-storage + Lead 集成）

### 3.1 模块

`app/core/storage_backend.py`：
```python
class StorageBackend(Protocol):
    name: str
    def save_file(self, local_path: Path, key: str) -> int: ...
    def download_file(self, key: str, dest: Path) -> None: ...
    def open_range(self, key: str, start: int, length: int) -> Iterator[bytes]: ...
    def open_stream(self, key: str) -> Iterator[bytes]: ...
    def exists(self, key: str) -> bool: ...
    def size(self, key: str) -> int: ...
    def delete_prefix(self, prefix: str) -> None: ...
    def list_prefix(self, prefix: str) -> list[str]: ...
    def presigned_url(self, key: str, expires_sec: int = 3600) -> str | None: ...
def get_storage() -> StorageBackend  # 根据 settings.storage_backend 单例
```
- key 规范：`media/{uuid}/original{ext}`、`media/{uuid}/playback.m4a`（原 `storage_dir` + 文件名即 key）。
- LocalStorage：root = data_dir；local 路径与 v0.2 完全一致。
- S3Storage：boto3 lazy import；`ECHOIC_S3_*` 配置；bucket 缺失/连接失败 → 启动/健康检查 degraded 并在上传时给中文错误；`path_style=True` 支持 MinIO；`delete_prefix` 批量删除。
- `app/tools/storage_migrate.py` CLI：`python -m app.tools.storage_migrate --from local --to s3 --dry-run|--apply|--verify`；逐 recording 复制原文件/playback；默认保留源；输出统计；失败可重试。
- health：`GET /api/system/health` 增加 storage backend 状态（ok/degraded）。
- 媒体：S3 模式下默认同源代理 Range（服务端 `open_range` 流式）；`ECHOIC_S3_PRESIGN_REDIRECT=true` 时 307 到预签名 URL（Safari/私有网络兼容性自测）。
- 管线：Lead 集成——prepare 前把 original 取到本地临时目录，产出 playback 上传；media/删除/迁移使用 storage。demo seed / consume 上传走 storage。

## 4. R-19 实时转写 Beta（backend-ai + frontend）

### 4.1 API

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/live/sessions` | body `{language?, merge_mode?}` → 201 `{id,uuid,status,provider,model,merge_mode,ws_url,started_at}`；`ECHOIC_LIVE_ENABLED=false` → 403 `LIVE_DISABLED` |
| GET | `/api/live/sessions/{id}` | owner/admin；会话状态 + 统计 |
| GET | `/api/live/sessions/{id}/segments` | 已确定片段列表 |
| POST | `/api/live/sessions/{id}/stop` | 幂等结束，返回 `{ok:true,status,total_audio_ms}` |
| POST | `/api/live/sessions/{id}/cancel` | 取消并丢弃 |
| WS | `/api/live/sessions/{id}/stream` | 实时音频双工，见下 |
| GET | `/api/recordings/{id}/live` | 绑定到该录音的实时会话 + 片段（详情页展示“实时稿”） |

WS 协议：
- 鉴权：Cookie `echoic_token` 或 `?token=<jwt>`；非 owner/admin → close 4403；未启用 → 4403；非 active → 4409。
- 客户端：连接后可先发 JSON `{"type":"start","sample_rate":16000,"channels":1}`（可省略）；随后发送**二进制 PCM16LE 16kHz mono** 音频帧（建议 20–100ms/帧）；结束发 `{"type":"stop"}` 或直接 close。
- 服务端 JSON 事件：`{"type":"ready"}` / `{"type":"partial","text":"…","start_ms":0,"end_ms":1200}` / `{"type":"final","text":"…","start_ms":0,"end_ms":2000,"speaker_label":null}` / `{"type":"error","message":"…","code":"…"}` / `{"type":"done","total_ms":…}`；服务端可主动 close 1000。
- 背压：服务端用 asyncio.Queue 缓冲；超过上限（如 10s 音频）返回 error 并关闭。
- 上限：`ECHOIC_LIVE_MAX_MINUTES`，到时发送 error + done 并结束。
- 会话与录音绑定：上传接口 multipart 新增可选 `live_session_id`；绑定后 worker pipeline 完成后：
  - `replace`（默认）：保留离线 ASR 转录（含说话人）为最终稿；实时稿存于 live 表，可通过 `GET /api/recordings/{id}/live` 查看；会话状态 `merged`。
  - `promote`：用实时稿（单说话人）作为最终 transcript 并重算 insights；若离线 ASR 失败且存在实时会话，自动回退 promote。
- Provider：`mock` 实时 provider 必须可在无 Key 下演示（demo fixture 按音频时长渐进输出）；`dashscope_realtime` 走 Research 文档中的 WS 协议（run-task/二进制帧/finish-task），失败给中文错误；重连不做自动化（文档标注 Beta）。
- 前端：录音页开始录音时若 `/api/system/features` 的 live.enabled 为真则创建 live session + AudioWorklet 采集/重采样 16k PCM + WS 推送 + 实时字幕面板（partial 覆盖末行/final 追加），停止时等待 done，再上传音频并带 live_session_id；失败自动降级为普通录音。详情页若存在实时稿则显示“实时稿（Beta，未区分说话人）”入口。
- 不要求实时说话人分离；文档/UI 明示“完成后以离线转写为准”。

## 5. R-20 向量/混合检索 Phase 1（backend-search + frontend）

### 5.1 模块与数据

- 现有 `chunks.embedding`（float32 BLOB）+ `dim`；新增 `embedding_model`。
- `app/services/vector_store.py`：
  - `NumpyVectorStore`：按可见录音范围加载 chunks 矩阵（内存缓存，key 含 recording_id+更新计数），余弦相似度，top-k + min_score；默认/auto 后端。
  - `PgVectorStore`（experimental，PG + pgvector 扩展时启用）：启动 `CREATE EXTENSION IF NOT EXISTS vector`，懒创建 `chunk_vectors(chunk_id PK, embedding vector(dim))`；不可用自动降级 numpy 并记录原因；本地无 pgvector 环境，必须优雅降级 + 文档标注。
  - `get_vector_store()` 根据 `ECHOIC_VECTOR_BACKEND`。
- `app/services/retrieval.py`：`retrieve_for_query(db, user, query, mode, limit)` → 关键词/语义/混合（RRF）统一结果，带 ACL 过滤、score、segment 信息；`retrieve_for_chat(db, recording_id, query)` 供聊天用（Lead 集成）。
- mock embeddings provider：`app/providers/embeddings_mock.py`（确定性 char-ngram 哈希向量，dim 256），settings 允许 `mock`（仅演示/测试）。
- reindex：遍历可见（admin）录音的 segments→chunks，调用当前 embedding provider 批量写入 embedding/model；批大小 ≤10，断点/失败计数；`force` 重算已有；不改变 transcript。
- CLI：`python -m app.tools.vector_reindex --all [--dry-run] [--recording-id ID] [--force]`。

### 5.2 API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/vector/status` | admin：`{backend,available,embeddings_configured,embedding_model,dim,chunks_total,chunks_indexed,stale_chunks,fallback_reason}` |
| POST | `/api/vector/reindex` | admin：`{recording_ids?, force?, dry_run?}` → `{ok,processed,chunks,skipped,errors}`；同步执行，单次 ≤200 录音（超限 400）；embedding 未配置 → 400 |
| GET | `/api/vector/search?q=&mode=hybrid|semantic&limit=` | 登录用户；ACL（admin 全部/member 自己的）；`{query,mode,results:[{recording_id,title,segment_id,speaker,start_ms,text,score}],fallback_reason?}`；embedding 未配置或索引为空 → 降级关键词并给 `fallback_reason` |

- 聊天 RAG：Lead 在 `services/chat.py` 中接入 `retrieve_for_chat` 混合检索（无向量时行为与 v0.2 等价）。
- 前端：
  - 搜索页增加模式切换「关键词 / 混合 / 语义」；语义不可用时禁用并显示原因；结果带 score 与高亮；点击结果跳转录音并 seek。
  - 设置 → AI 服务：Embeddings 支持 `mock`（演示）；设置 → 系统新增「检索索引」卡片：后端/模型/已索引/过期数量、重建按钮（admin）、dry-run 结果提示。
  - 录音上传/处理完成无需额外操作（pipeline 配好 embeddings 时自动建索引）。

### 5.3 验收
